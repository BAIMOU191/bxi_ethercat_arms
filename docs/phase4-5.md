## 工具入口

- 启动时用 --check、--no-check 或 --check-motor 1|0 覆盖 safety.check_motors；-m/--mask/--motor-disable 覆盖 safety.ignore_mask。未指定时读取配置。保留具名参数，避免把参考程序的上电参数误当作屏蔽掩码。
- help 从同一份命令表生成分组、摘要与逐条帮助。check 检查已打开的关节并打印生效策略；selftest 另检查驱动器故障和保护锁定。自检不使能、不运动。不在线且在启动时跳过的关节不会被 check 加回。
- info 21 查看映射、方向、偏置、回零位置、指令限幅和反馈保护阈值；identify 21 读取 0x1018 的厂商、产品、修订与序列号。身份读取不等于现场物理映射已验证。status 21 --raw 的 TxPDO 是从站发出的 16 字节，RxPDO 是主站准备发送的 23 字节，不是示波器或线上抓包。
- pn 21 Pn075、sdo 21 0x1018 4、reg 21 0x130 2 这三个示例都只读取，不写入。`pn` 和 `sdo` 可带写值，`reg` 仅支持读。SDO 返回小端字节；ESC reg 支持 1、2、4 字节读，不提供任意寄存器写。模拟 ESC 只实现 AL Status；不把虚构的读数冒充设备响应。

## 维护边界

在有机械支撑、现场可急停并确认对应编号后，才可对真实设备做维护。维护命令与运动命令在同一会话中使用，CLI 写操作以回车提交，ROS 服务收到请求即进行相应操作的状态检查，两者都不需要额外的人工确认；通信健康检查、编码合法性和驱动状态检查仍生效。brake、zero、pn_save 可选择任意关节组合（单个、单臂或 all）。启动时读取各关节 Pn075，非 normal 的关节会告警；失能时显示为 released / held，已使能时仍显示 enabled（用 `brake <关节>` 查询模式）。任一已打开关节非 normal 时，拒绝新的 enable、free 请求；读不到模式时同样拒绝这两个操作。用手拖动关节用 free（使能后 kp=0）：驱动器失能时电机阻尼很大，仅强制松闸仍难以转动。KGU 驱动器的 0x1018:04 序列号为 0，不能用于区分电机；关节号与实物的对应关系需在现场逐个核对（例如对单个关节执行 free 后手动转动，或小幅度 mit 动作）。

| 功能 | 实际行为 |
|---|---|
| brake | 不带模式时读取 Pn075；normal / release / hold 分别写入 0 / 1 / 2 并回读，只临时修改不保存。三种模式均可在使能或失能时切换，不切换伺服或撤销目标；强制模式不在故障、保护或伺服过渡态下写入。先停止运动指令、确认静止并支撑负载，不要用强制抱闸来停车。退出时尝试将本次改动过的关节恢复为 normal。Pn 回读不是机械制动器闭合反馈；通信中断时不能保证软件能改回抱闸模式。 |
| free | 未使能的关节先使能，然后 kp=0、速度和前馈为 0、阻尼取参数 kd（默认 0，不超过 gain_max.kd）。先支撑关节再 disable。hold 保留 kp=0，不会恢复位置保持力。 |
| zero | 软件零位用方向乘以实际原始位置得到新 offset_rad；只替换该关节 offset_rad 的数值、保留文件其余内容，写临时文件、重新解析校验后原子替换，并**立即生效**。请先托住并停在目标姿态；已使能的关节自动失能，已失能的不重复操作。最多等待 1 秒，须实际反馈失能且观测到至少 50 ms 静止（速度绝对值不超过 0.01 rad/s），否则该关节不写入。完成后不重新使能。记录当前机械姿态不是移动到 home。mock 测试请给 -c 指定配置副本，软件零位确实写文件。 |
| zero --hw | 沿用相同的按需失能和静止检查，另要求该关节抱闸为 normal；核实 Pn101 初值，触发后回读并复位。之后按驱动手册重启、验证坐标及原软件偏置。 |
| pn / sdo 写 | 普通写不按手册目录或手册范围拦截，权限交给从站；应用层保留失能和故障检查。已编号的动作走原专用流程，不开放 PDO 控制字或原始 ESC 写。 |
| pn_save | 先可靠支撑负载，尤其是强制松闸的关节。保存不检查或更改 Pn075；只对选中关节按需失能，并按与 zero 相同的条件确认静止，完成后不重新使能。Pn097 初值必须为零，触发、回读、等待、复位并回读。多关节逐个执行并报告结果。脉冲回读不证明掉电持久化；哪些参数被保存须按模组说明和重新上电后的回读确认。 |

没有非实时 EtherCAT 管理操作在 PDO 线程里等待。软件不能替代硬件急停、STO、支撑或现场断电确认。不要把本程序与不遵守会话锁的旧控制器同时运行。

## 部署

1. ROS 构建与 mock 冒烟见 arms_ros/README.md。服务使用只读、由 root 管理的安装前缀；不要让 root 服务 source 普通用户可写的工作区。EtherLab 和现有 communication 是运行依赖。
2. deploy/master-plan.py 读取配置与网卡实际 MAC，打印建议的 MASTERn_DEVICE，不改 /etc。比较现有 /etc/sysconfig/ethercat，保留其他主站。内核核隔离和 PCI 电源归属属于整机配置，本项目不改内核启动参数。
3. 按现场规范部署 ROS overlay 到 /opt/bxi/arms-install（或修改 env）。deploy/install-service.sh 只安装服务、默认配置及环境文件，不覆盖已有配置，不启动、不开机启用。检查 /etc/bxi/arms-node.env 的前缀、电源所有者及 ROS 域。
4. 实时设置放在节点已经取得互斥锁之后执行，清理在释放锁之前完成，避免独立 oneshot 服务与测试工具争用。节点依赖现有 ethercat.service。systemd 不自动重启节点，避免故障后反复上电。服务配置默认 **不接管电源**；外部供电时断电保护必须由整机电源所有者落实。现场签核后再决定是否启用服务。

## 验收清单

- 软件：板端编译真实 EtherLab 与 PCI 分支；CTest 验证启动开关、缺站/屏蔽、恢复、互锁、维护回读、配置写入与命令帮助。独立 ROS 域上用 mock 验证状态、诊断、控制目标、显式使能和抱闸服务互锁。
- 现场待验收：逐关节读取并核实 15–28 的型号、序列号、方向、Pn082 与承重关节初始 Pn075；有支撑时检查抱闸与零位；记录实机参数掉电前后值；物理回读掉线保护是否断电。系统测试包括带负载时 1/2 kHz 双臂抖动、整机话题兼容和真实冷启动。不要从模拟结果推断这些项目已通过。

### Pn 参数目录

- `pn list`、`pn help <编号或别名>` 和 Tab 用的是 KGU EtherCAT V1.2 手册参考表，不在线扫描设备，也不决定权限。Pn075/097/101 是受管理的动作（如下）；普通对象不按型号修订、目录成员、手册范围或枚举拒绝传输。驱动器有可能接受对机构并不安全的值，修改前仍须核对实物与手册。
- `pn <单关节> <000..999> [INT16]`，编号按十进制，自动换算到对象索引、子索引 0；既可读也可写。`pn 15 Pn026`、`pn 15 brake_voltage`、`brake_voltage 15`、`sdo 15 0x2026 0` 读同一对象。两条别名输入原始整数；`torque_scale` 原始 12 表示 1.2 A/N·m。手册中的 Pn0150 在命令中写作 Pn150。该版 ESI 有重复的 Pn071 标签，请按实际对象地址区分。
- `sdo <单关节> <索引> <子索引> [值]`：可访问未列出的对象和非零子索引。写值默认 i16；其他整数用 `i8:`、`u8:`、`i16:`、`u16:`、`i32:`、`u32:`、`i64:`、`u64:` 指定；整数可用十进制或 `0x`。`hex:` 后接连续偶数个十六进制字符，按给出的字节顺序原样下载。不能根据值大小猜对象宽度，请先查实际对象字典。CLI 单次上传缓冲区为 4096 字节，命令行长度上限 511 字节。
- 普通写要求关节在线、反馈新鲜、已失能、无故障/保护；不自动失能。不要求对象能够读取：只发送一次下载，不先试读、不自动回读、不自动保存。成功只表示驱动器接受，若需校验，对可读对象另发读命令。从站拒绝时显示原始 SDO abort。只有主站正在接管的实时输出（控制字、模式、MIT 目标）、使用中的 PDO 映射与分配不并行写。`reg` 仍只读，ROS 未开放通用参数写服务。
- Pn075 的 0/1/2 走原 `brake`；Pn097 和 Pn101 **只接受写 1 启动完整动作**，分别等价于 `pn_save` 和 `zero --hw`。程序自己完成失能检查、脉冲回落与回读，拒绝手动写 0；硬件校零的抱闸检查不变。软件 `zero` 不经过 Pn101。
